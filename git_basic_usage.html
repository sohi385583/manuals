GitHub の基本操作マニュアル

カテゴリー: Version Control | 最終更新: 2026年7月21日

1. 概要・用語整理

Gitは分散型バージョン管理システムであり、GitHubはそのコードをクラウド上で保存・共有するためのWebサービスです。

  • ローカルリポジトリ: 自分のPC内にある作業用リポジトリ
  • リモートリポジトリ: GitHub上にある共有リポジトリ（origin）
  • コミット (Commit): ファイルの変更履歴を記録する単位
  • プッシュ (Push): ローカルのコミットをGitHubに送信する操作
  • プル (Pull): GitHubの最新状態をローカルに取得・統合する操作

2. リポジトリの準備

既存リポジトリを自分のPCに複製（Clone）

GitHub上のプロジェクトをローカル環境にダウンロードします。

# HTTPSでクローンする場合
git clone https://github.com/username/repository-name.git

# クローンしたディレクトリへ移動
cd repository-name

3. 日常の開発フロー

基本となる「編集 → ステージング → コミット → プッシュ」の流れです。

1. 変更状態の確認

どのファイルが編集・追加されたか確認します。

git status

2. ステージング（Indexへの追加）

コミット対象のファイルを選択します。

# 特定のファイルをステージング
git add path/to/file.ext

# 変更された全ファイルをステージング
git add .

3. コミット（変更の記録）

分かりやすいコミットメッセージを添えて変更を記録します。

git commit -m "feat: 〇〇機能の追加"

4. プッシュ（GitHubへの送信）

# mainブランチへ送信する場合
git push origin main

Point: 作業前には必ず git pull origin main を実行して、リモートの最新状態を取り込んでから作業を始めましょう。

4. ブランチ運用

機能追加やバグ修正は、直接 main を編集せず専用のブランチを作成して作業します。

ブランチの作成と切り替え

# 新しいブランチを作成して切替
git checkout -b feature/login-page

# （Git 2.23以降の新しいコマンド表現）
git switch -c feature/login-page

ブランチ一覧の確認

git branch -a

作業完了後のプッシュ

git push origin feature/login-page

プッシュ後、GitHub上で「Pull Request (PR)」を作成し、レビューを経て main ブランチへマージします。

5. よくあるトラブル解決

誤ってコミットメッセージを間違えた時

git commit --amend -m "正しいコミットメッセージ"

ローカルの直前の変更を取り消したい時

# ステージングを取り消す（ファイルの編集内容は保持）
git restore --staged path/to/file

# 編集内容自体を破棄して直前コミットに戻す
git restore path/to/file
